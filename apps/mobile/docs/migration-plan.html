Overview

A ground-up rebuild of the Mealawe customer app on a single modern React Native codebase, wired to the live Mealawe backend, shipping every ordering vertical without regressing behaviour. Behaviour follows MealaweUserApp (Angular 16 / Ionic 7); ported logic references the cleaned-up mealaweApp (Ionic 8).

Phase 1 — Foundation DONE

Establish the shared platform every feature builds on.

  • Project structure — feature-first folders under src/features/<domain>, shared UI in src/components/ui, services in src/services, state in src/store.
  • Design system — brand tokens (green, yellow, cream, teal), the AppText Lato typography primitive, a Lucide icon set; documented in DESIGN.md.
  • Theming — light / dark / system with a persisted preference applied through React Native Appearance; switchable from the profile. Defaults to system.
  • API transport & encryption — a fetch client porting the Ionic AES session_x scheme: every request body encrypted to { data_key }, every response decrypted with a per-request key.
  • Storage — encrypted secure store for session + profile; MMKV for fast state (address, theme, drafts).
  • Auth state — a Zustand store hydrating on boot, exposing the token to the HTTP client, driving the routing gate.
  • Routing — Expo Router with a boot gate and typed routes.
  • EAS baseline — eas.json, project linked, runtime versioning + OTA channel.

Acceptance: app boots, encrypted requests succeed, session & theme persist, typecheck and Android export green.

Phase 2 — Onboarding & Authentication DONE

  • Welcome — three-slide onboarding carousel.

Acceptance: address selection updates home context; wallet, cashback, help, feedback call live endpoints.

Shared building blocks for the ordering verticals

Phases 4–9 each deliver one ordering vertical over the same spine, built once and reused. Each vertical layers its own catalogue and business rules on top.

  • Vertical home — hero / banners, coupons, entry into the menu.
  • Catalogue & menu — items, weekly menu where applicable, cluster-wise (serviceable-area) availability, and categories.
  • Cart & pricing engine — one tested calculation module: item totals, add-ons, GST, delivery, packaging, platform fees, coupons, and wallet / cashback redemption. Bill math mirrors the Ionic tabCart per vertical.
  • Payments — one service with both live gateways (JusPay HyperSDK, Paytm All-in-One) switched by config, plus order creation and payment validation.
  • Orders — parent order → child orders → daily orders, each with live status and a delivery map where relevant.

Acceptance (per vertical): browse → add to cart → correct bill → pay → order created → track status.

Ordering-vertical checklist (Phases 4–9)

  • Vertical home (hero, banners, coupons)
  • Menu: items · weekly menu · cluster-wise menu · categories
  • Cart with full pricing (items, add-ons, GST, charges, coupons, wallet / cashback)
  • Payment gateway (JusPay / Paytm) + order creation + validation
  • Orders: parent → child → daily, with delivery map and live status
  • Empty / error / loading states and serviceability conditions

Key risks & dependencies

  • Payment SDKs are native and gateway-specific — validate the native build early per gateway.
  • Cluster / serviceability logic gates catalogue and tabs — port it faithfully.
  • Bill math must match the backend to the paisa — reuse one engine and test it hard.
  • Google & Firebase keys must be enabled for the app's package and signing certificate.
  • App identity is shared with production (com.mealawe.app) — manage versionCodes via EAS remote versioning to avoid install conflicts.
